# RestroGrow Super Admin app

The Super Admin panel as a phone app (Expo / React Native, same stack and design kit as the
Partner app in `../app`). It talks to the same backend as `main/superadmin/dashboard.php`, so
everything done here shows up in the web panel and in **Activity log**.

## Run it

```bash
cd superadmin-app
npm install          # first time only
npm run web          # browser, http://localhost:8082
npm start            # phone: scan the QR code with Expo Go
```

XAMPP (Apache + MySQL) must be running. In development the app calls the address it was
loaded from and `metro.config.js` forwards `/menuwebsite/*` to XAMPP, so the PHP session cookie
works in the browser and on a phone, with no CORS setup. Release builds call `https://restrogrow.com`.

Port 8082 keeps it from clashing with the Partner app (8081), so both can run at once.
If you start Metro with `CI=1` it does not watch files: restart it after changes.

## Build the Android APK

Same toolchain as the Partner app (JDK 17 and Android SDK in `C:\Users\INDIA\dev`):

```bash
cd superadmin-app/android
JAVA_HOME="C:\Users\INDIA\dev\jdk17" ./gradlew assembleRelease
# -> android/app/build/outputs/apk/release/app-release.apk
```

`android/` is generated by `npx expo prebuild --platform android` and is not in git. After a
fresh prebuild, put back the local settings:

- `android/gradle/wrapper/gradle-wrapper.properties`: `distributionUrl=file:///C:/Users/INDIA/dev/gradle-9.3.1-bin.zip`
- `android/local.properties`: `sdk.dir=C:/Users/INDIA/dev/android-sdk`
- `android/gradle.properties`: the `Windows-ROOT` trust store, IPv4 and HTTP timeout lines from
  `../app/android/gradle.properties`, and `reactNativeArchitectures=armeabi-v7a,arm64-v8a`

The release APK is signed with the debug key, like the Partner app.

**The APK talks to https://restrogrow.com.** Deploy `main/superadmin/app_auth.php` and the
updated `main/superadmin/api.php` to the live site first, or sign-in and the Restaurants
filters won't work there.

## What's in it

| Tab | What you can do |
|---|---|
| **Overview** | MRR / ARR, paying / trial / lapsed counts (tap to open the filtered list), orders today and this month across all restaurants, 12-month revenue chart, top restaurants, at-risk restaurants, unread tickets / renewals due / new leads |
| **Restaurants** | Search, filter by plan (All / Paying / Trial / Ending soon / Expired / Disabled, with counts), add a new one (suggested password, then share the login details). Tap one for its 360: plan and days left, activate (30 days / 3–24 months), extend, mark expired, WhatsApp renewal reminder, sales and 14-day chart, account details, link to their website, feature switches (install-app, WhatsApp orders, gallery, meal plans, online payments), reset password, clear OTP lock, enable / disable, payments, sign-ins, errors. In the browser: open their dashboard |
| **Renewals** | Plans ending in 7 / 15 / 30 / 60 days and those expired in the last 30, with WhatsApp reminder, +7 and +30 days |
| **Support** | Tickets by status, the full thread with the restaurant's recent orders and errors, quick-reply templates, reply and mark answered / closed, change status |
| **More** | Leads (pipeline, notes, follow-ups, add / edit / delete), Chatbot conversations, Payments (subscription stats, recent payments, invoices by month), Announcements (create, target restaurants, start / stop, delete), Security (sign-in stats, suspicious IPs, unblock IPs, sign-in log), Activity log, Platform health, Settings (plan prices, trial length, invoice / GST details, test email, fingerprint app lock), sign out |

When the server can't be reached a small "No connection" strip appears, screens keep their last
data, and everything reloads by itself once the connection is back.

Menu editing, coupons, branch admins, payment links and settlements stay in the web panel
(More › Open full web panel).

## Backend

- `main/superadmin/app_auth.php`: JSON sign-in / session / sign-out for this app (same
  `super_admins` table, session keys and rate limit as `login.php`).
- `main/superadmin/api.php` `getRestaurants` takes an optional `status` filter and `with_counts=1`
  (additive; the web panel doesn't send them, so it is unchanged).
- Everything else uses the existing `api.php` and `api_platform.php`.

## Layout

```
App.js                 navigation: sign-in, app lock, 5 tabs, shared detail screens, offline strip
config/api.js          backend calls (auth, sa = api.php, pf = api_platform.php), online / offline state
context/AuthContext.js session, sign in / out, auto sign-out when the session expires
components/            kit.js (Card, Pill, Button, Field, Row, Chips, Metric...), Screen, TabBar,
                       ConnectionBanner, plus the Partner app's header, sheets, toasts and skeletons
screens/               one file per screen
utils/badges.js        shared poll for the tab-bar badges
assets/                navy "Super Admin" icon, adaptive icon and splash
```
